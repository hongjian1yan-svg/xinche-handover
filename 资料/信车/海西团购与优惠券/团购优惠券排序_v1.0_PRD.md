# 团购/优惠券自定义排序 PRD（独立交付版）

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v1.0 |
| 日期 | 2026-11-09 |
| 覆盖端 | 信车 PC 后台（团购商品、优惠券配置）、海西微信小程序 |
| 范围说明 | 本文件为《V3.1海西团购迭代升级_PRD》中排序与待上架相关规则的独立交付版，规则以 V3.1 原文为准，不含海西团购迭代其他功能 |

## 1. 背景与目标

运营需要可控地决定小程序中团购与优惠券的展示顺序，因此 PC 后台为团购商品、优惠券配置分别提供自定义排序号能力，小程序列表按排序号展示。

## 2. 通用排序规则（团购与优惠券共用）

| 规则项 | 口径 |
| --- | --- |
| 排序号形态 | 正整数；数字越小越靠前 |
| 独立性 | 团购与优惠券独立排序，互不影响 |
| 维护维度 | 按所属市场分别维护排序号 |
| 唯一性 | 同一市场、同一类型中，当前参与排序的记录排序号不可重复 |
| 必填 | 排序号必填；新建表单清空后提交按必填校验拦截 |
| 新建默认值 | 预填当前所属市场中该类参与排序记录的最大排序号 + 1，即默认排在该市场该类末尾 |
| 下架释放 | 记录下架后不参与当前排序、不占用排序号；排序列显示「—」；其他参与排序记录的序号与顺序不变，不自动补位或重编号，可留空号；手动修改或新建可重用释放的序号 |
| 重复占用计算 | 待上架记录（团购的到期自动上架待上架、优惠券的待上架）参与排序并占用排序号；排序号唯一性校验与新建默认最大排序号 + 1 的计算均包含待上架记录 |
| 初始化 | 旧内容初始化时保留小程序当前展示顺序 |
| 修改入口 | 已有记录的排序号通过该行「操作 - 更多操作」修改；表格排序号单元格只显示数值，不增加按钮 |
| 冲突替换 | 修改已有记录时，输入的正整数被同一市场其他参与同类型排序的记录占用：显示文字提示「排序号已被占用，可替换位置」（提示文字为错误红色 `#f56c6c`，2026-11-09 YAN 确认），主按钮改为「替换位置」；点击后两条记录的排序号互换 |
| 新增拦截 | 新增团购/优惠券时排序号重复：提示并拦截提交，不可替换 |
| 再次设置 | 已下架记录再次设置/再次配置时复制旧配置至新建表单，创建新记录、新 ID，不复活原记录；旧记录保持下架，历史领取/订单关系保留；新表单全部内容可编辑并可配置排序号，默认值为当前市场该类参与排序记录的最大排序号 + 1 |

## 3. 团购商品排序

### 3.1 列表

- 列表增加「排序号」字段，可修改（修改入口与冲突处理见第 2 节）。
- 列表上方状态 Tab 为：待上架、上架中、已下架。
- 上架类型为「到期自动上架」的团购，在预设上架时间未到前归入 PC「待上架」，已配置排序号参与排序并占用所属市场团购排序位，其他记录不可占用该排序号。
- 到达预设上架时间后自动转入「上架中」，沿用创建时的排序号，不重排或重新分配。

### 3.2 新建/再次设置表单

- 「排序号」为第一步「团购基本信息」必填字段：正整数，数值越小越靠前；打开新建表单时预填当前所属市场中参与排序的团购记录（含待上架的到期自动上架团购）的最大排序号 + 1；清空后提交按必填校验拦截；重复时提示并拦截提交，不可替换。
- 已下架团购再次设置按新记录处理，规则见第 2 节「再次设置」。

### 3.3 下架

- 团购下架后排序列显示「—」，原排序位释放；其余口径见第 2 节「下架释放」。

### 3.4 小程序展示

- 超值团购列表按所属市场的团购排序号从小到大展示；现有筛选和分页保持该顺序。
- 待上架的到期自动上架团购在预设上架时间前不在小程序展示；PC 状态本身不替代现有上架/有效条件。
- 再次设置的新记录须符合现有上架/有效条件才展示，并按新记录排序号排列。

## 4. 优惠券配置排序与待上架

### 4.1 列表与状态 Tab

- 内容区状态 Tab 依次为「待上架」「已上架」「已下架」，分别查看对应状态的优惠券；默认选中「待上架」。Tab 仅用于区分列表状态，不改变其他业务流程；列表不展示「状态」列。
- 列表最左侧「排序」列展示排序号，可修改（修改入口与冲突处理见第 2 节）。

### 4.2 待上架判定与流转

| 规则项 | 口径 |
| --- | --- |
| 判定条件 | 「领取时间」配置为「限制」，且当前时间早于所选开始日期时，视为「待上架」 |
| 时间口径 | 按服务器当前时间与领取开始日期比较，精确到日；跨天自动切换后列表按新状态归类，页面无需刷新 |
| 自动流转 | 到达开始日期 00:00 自动转入「已上架」，无需人工操作，沿用原排序号 |
| 已下架优先 | 其余情况按「已上架」「已下架」判定；已下架优先，不回退到待上架 |
| 排序占位 | 待上架优惠券占用所属市场优惠券排序号并参与排序，与团购到期自动上架的占位口径一致；唯一性校验与新建默认最大排序号 + 1 的计算均包含待上架记录 |
| 下架释放 | 已下架显示「—」并释放排序位 |

### 4.3 待上架操作

- 操作列与「已上架」一致，更多操作包含「修改排序」「编辑」「下架」「操作日志」。
- 「下架」即取消该券的待上架，确认后进入「已下架」；二次确认样式与文案沿用现有下架确认弹窗（提示文案「确认下架该优惠券？」）。
- 待上架不支持「再次设置」。

### 4.4 筛选与 Tab 联动

- 切换状态 Tab 时清除「状态」筛选，取得所选 Tab 对应列表。
- 「状态」筛选下拉保持「全部 / 已上架 / 已下架」不变，不新增待上架选项，避免与 Tab 双维度冲突。

### 4.5 详情状态标签

| 状态 | 标签颜色 |
| --- | --- |
| 待上架 | 橙色（警告色系 `#E6A23C`） |
| 已上架 | 绿色 |
| 已下架 | 红色 |

- 待上架优惠券点击「查看」时，详情抽屉中状态字段展示「待上架」。

### 4.6 新建/再次配置表单

- 「排序号」为第一步「优惠券基本信息」必填字段：正整数，数值越小越靠前；打开新建表单时预填当前所属市场、对应类型下参与排序记录的最大排序号 + 1；清空后提交按必填校验拦截；重复时提示并拦截提交，不可替换。
- 已下架优惠券再次配置按新记录处理（复制旧配置至新建表单、新 ID、旧记录保留历史领取/订单），规则见第 2 节「再次设置」。

### 4.7 小程序展示

- 会员福利列表按所属市场的优惠券排序号从小到大展示；现有筛选和分页保持该顺序。
- 「领取时间」配置为「限制」且当前时间早于所选开始日期的优惠券不在小程序展示：不出现在会员福利列表、停车领券列表、车况查询优惠券区及团购详情「立即领券」可跳转范围；不展示期间卡片不置灰、不给 Toast 提示；列表为空时按既有空态处理；已领取用户不受影响。
- 到达开始日期后按原排序号自动恢复展示，无需人工操作。

## 5. 小程序侧汇总

- 会员福利、超值团购列表仅展示符合现有上架/有效条件的内容，各自按所属市场对应类型排序号从小到大展示；筛选、分页后仍保持该顺序；旧内容初始化保留小程序当前展示顺序。
- 待上架的到期自动上架团购在预设上架时间前不展示；领取时间未开始的优惠券不展示。
- 本期不新增小程序侧其他排序交互。

## 6. 技术与数据要求（业务约束）

- 排序号需持久化到后端；排序号唯一性在服务端二次校验，不依赖前端拦截。
- 「待上架」为派生状态，禁止单独持久化待上架状态，由领取时间/上架时间 + 当前时间计算得出。
- 到期自动切换（团购到期自动上架、优惠券到达开始日期 00:00 转入已上架）通过定时任务扫描到点自动切换，无需人工操作，沿用原排序号。
- 排序号变更需记录操作日志（复用现有操作日志弹窗：操作人、操作介绍、操作时间）。

## 7. 验收标准

### 7.1 通用

- [ ] 排序号仅接受正整数，数字越小越靠前；必填，清空提交被拦截。
- [ ] 团购与优惠券独立排序；同一市场同一类型参与排序的记录排序号不可重复。
- [ ] 新建表单预填当前市场该类参与排序记录的最大排序号 + 1；新增时重复提示并拦截，不可替换。
- [ ] 修改排序号入口仅在该行「操作 - 更多操作」，表格单元格只显示数值。
- [ ] 修改时输入被占用的排序号，显示「排序号已被占用，可替换位置」提示（错误红色）及「替换位置」主按钮；点击后两条记录排序号互换。
- [ ] 下架后排序列显示「—」、释放排序位；其他记录不补位、不重编号；可重用释放的序号。
- [ ] 已下架记录再次设置创建新记录、新 ID，旧记录保留历史领取/订单；新表单可配置必填排序号。
- [ ] 旧内容初始化保留小程序当前展示顺序。

### 7.2 团购

- [ ] 团购列表含可修改的「排序号」字段。
- [ ] 到期自动上架团购在上架时间前归入「待上架」Tab，占用排序位，冲突校验与最大号默认值计算包含该记录。
- [ ] 到达预设上架时间自动转入「上架中」，沿用原排序号，不重排、不重新分配。
- [ ] 小程序超值团购按排序号升序展示；未到预设上架时间的团购不提前展示。

### 7.3 优惠券

- [ ] 状态 Tab 为「待上架/已上架/已下架」，默认选中「待上架」；列表不展示状态列。
- [ ] 「领取时间」=「限制」且未到开始日期的券归入待上架；到达开始日期 00:00 自动转入已上架并沿用排序号；判定按服务器时间精确到日，跨天切换页面无需刷新。
- [ ] 已下架优先，不回退到待上架。
- [ ] 待上架占用排序号并参与唯一性校验与新建默认最大号 + 1 计算。
- [ ] 待上架操作列与已上架一致（修改排序、编辑、下架、操作日志）；下架经「确认下架该优惠券？」二次确认，确认后进入已下架；待上架不支持再次设置。
- [ ] 切换 Tab 清除「状态」筛选；筛选下拉不新增待上架选项。
- [ ] 详情状态标签：待上架橙色 / 已上架绿色 / 已下架红色；待上架详情状态字段展示「待上架」。

### 7.4 小程序

- [ ] 会员福利、超值团购分别按所属市场对应类型排序号升序展示，筛选、分页后保持顺序。
- [ ] 待上架团购/领取时间未开始的优惠券不展示；不置灰、无 Toast；到达开始日期后按原排序号自动恢复展示；已领取用户不受影响。
