## 1. 项目背景

海西小程序需支持用户先领取优惠券，再完成停车缴费、车况查询或购买线下核验团购产品。现有团购配置继续承担产品配置职责；优惠券规则从团购配置中拆分，由独立优惠券配置页维护。

## 2. 目标与范围

### 2.1 项目目标

- 建立停车缴费、车况查询、线下核验团购产品的统一领券与用券流程。
- 支持团购产品与优惠券独立配置、独立维护。
- 让用户在小程序中清晰了解优惠券适用品类、领取结果、实付价格与使用入口。

### 2.2 本期范围

| 端 | 本期内容 |
| --- | --- |
| 小程序 | 首页入口改版（会员福利 / 超值团购拆分）、会员福利领券、超值团购列表、停车缴费、车况查询、团购详情与选券下单、领取/购买成功页、个人中心「优惠券/团购」、非认证会员引导认证。 |
| PC 后台 | 复用既有团购配置作为产品配置载体；本期新增独立优惠券配置页。 |

### 2.3 不纳入范围

- 新建独立产品管理模块。
- 金额抵扣券、折扣券以外的优惠券类型。
- 车况产品维护方式调整；车况产品继续在车况初始化页面维护。
- 停车缴费业务能力改造；继续使用既有停车缴费业务。
- 团购列表外其他既有团购配置功能开发。
- 停车缴费记录相关页面开发。
- 车况查询“我的订单”页面开发。

## 3. 角色与术语

| 名称 | 定义 |
| --- | --- |
| 用户 | 使用海西小程序领取、使用优惠券及购买团购产品的用户。 |
| 团购产品 | 在团购配置中维护并展示给小程序用户的产品；可为原价产品或团购优惠产品。 |
| 优惠券 | 独立配置的金额抵扣券或折扣券，每张券仅绑定一个业务对象。 |
| 线下核验产品 | 用户线上下单支付后生成团购二维码，到店核销使用的团购产品。 |
| 原价 | 产品未应用团购优惠及优惠券时的价格。 |
| 实付价 | 先计算团购价，再计算优惠券后的用户支付金额。 |

## 4. 配置与数据规则

### 4.1 团购配置

- 团购配置仅维护产品、价格形态、购买方式与履约方式，不维护优惠券规则。
- 原价产品以普通商品形式在小程序展示，可使用关联且有效的优惠券。
- 团购优惠产品保留真实团购用途与团购优惠展示。
- 当团购商品以原价产品上架，且团购价与原价相等时，小程序列表仅展示红色价格，不展示删除线原价。
- 团购配置页面沿用既有产品、价格及履约能力；新增团购弹窗按本 PRD 第 6.2 节配置。

### 4.2 优惠券配置

- 每张优惠券仅绑定一个业务对象；同一业务对象可绑定多张优惠券。
- 支持金额抵扣券、折扣券；“免费领取”是领取方式，不是优惠券类型。
- 每张已领取优惠券仅可使用一次，使用后不可再次使用。
- 优惠券的所属市场、领取时间、使用有效期、总发放数量、每人领取次数、使用说明及是否可与团购优惠叠加均在 PC 端配置。
- 优惠券配置使用说明，限 500 字以内。
- 总发放数量和每人领取次数均支持“限制 / 不限制”；选择限制时配置具体数量或次数。
- 与团购优惠叠加默认关闭，可按优惠券单独开启。
- 「领取用户类型」「领取会员限制」与「用户类别」「会员限制」为两套独立配置、独立展示：前者约束谁可领取，后者约束谁可使用。

### 4.3 优惠券适用业务

| 适用业务 | 绑定对象 | 小程序使用方式 |
| --- | --- | --- |
| 原价商品 / 团购优惠商品 | 团购配置中对应类型的一个已上架产品 | 线上下单；线下核验产品支付成功后生成团购二维码。 |
| 车况查询 | 车况初始化中已维护的车况产品或套餐 | 领取后「去使用」直达该券绑定套餐的录入/下单页（不经车况产品列表）。 |
| 停车缴费 | 不绑定具体产品；列表与详情「绑定对象」展示「—」 | 输入车牌、选择可用停车券、在线缴费后道闸抬杆。 |

- 停车缴费券适用于所选市场内全部线上停车缴费订单，不绑定团购或具体停车产品。

## 5. 价格与选券规则

### 5.1 价格计算

- 原价产品可使用所绑定且当前可用的优惠券。
- 团购优惠产品默认不可再使用优惠券；仅当优惠券明确开启“可与团购优惠叠加”时，允许双重优惠。
- 计算顺序为：原价 → 团购价 → 优惠券抵扣或折扣 → 实付价。
- 实付价不得小于 0 元。

### 5.2 订单选券

- 停车缴费订单页、车况查询订单页及线下团购产品订单页均使用本节选券规则。
- 提交订单页的优惠券模块仅展示当前业务和绑定对象下可用的已领取优惠券；无可用券时展示“无可用优惠券”。【本次更新】
- 点击优惠券模块进入弹窗后，仅展示适用于当前业务和绑定对象的未使用优惠券；已使用优惠券不在弹窗中展示。满足业务和绑定对象、但不满足其他使用条件的优惠券置灰展示。
- 【本次更新】优惠券选择弹窗中，不可用优惠券的限制条件来自 PC 端优惠券配置项。
- 多张可用券时，默认选中按当前商品计算后实付金额最低的一张。
- 用户可点击已选优惠券，切换其他可用券或取消使用优惠券。
- 点击置灰优惠券时，按以下优先级 Toast 提示不可用原因（不含「该优惠券已下架」：优惠券下架不影响已领未用，选券弹窗保持现网、不出现该文案）：
  1. 该优惠券不在使用有效期内；
  2. 当前用户类型不满足使用条件；
  3. 当前会员身份不满足使用条件；
  4. 当前注册时间不满足使用条件；
  5. 当前注册时长不满足使用条件；
  6. 当前认证时间不满足使用条件；
  7. 您优惠券使用次数已达上限；
  8. 您今日优惠券使用次数已达上限；
  9. 您本月优惠券使用次数已达上限；
  10. 该优惠券不可与当前团购优惠叠加使用（仅团购价商品）。
- 停车券领取限制、总发放数量及每人领取次数只影响领券，不作为订单页的优惠券不可用原因。
- 【本次更新】若不可用原因为「非认证用户」，不走上述 Toast，改为弹窗引导认证（见第 7.9 节）；成为认证用户后，优惠券默认选中。

### 5.3 团购详情价格展示【本次更新】

团购详情页主价格按用户是否已领取该商品优惠券、以及当前是否按团购价售卖，分三种展示。列表、详情、提交订单（不选券）同一口径。

「存在团购价 / 按团购价售卖」须同时满足：团购类型为团购优惠商品、PC「商品团购价」开关为开、已配置团购价金额。开关关闭后按无团购价处理（展示原价），即使库中仍残留旧团购价数字。已购凭证、订单详情、退款仍用下单时实付，不随开关变化。

| 条件 | 主价格展示 | 原价展示 |
| --- | --- | --- |
| 已领取该商品优惠券 | 展示「券后价」文案与券后实付价格 | 展示商品原价（删除线） |
| 未领取该商品优惠券，且按团购价售卖 | 展示团购价格 | 展示商品原价（删除线） |
| 未领取该商品优惠券，且不按团购价售卖 | 展示商品原价 | 不额外展示删除线原价 |

- 商品原价、商品团购价及团购价开关均取自 PC 端团购配置。
- 券后价为 0 元时：红色主价格展示「免费」，不展示「￥0.00」；原价仍保留展示。底部主按钮文案可为「立即下单」（有金额时为「立即购买」），**仅区分文案，不改变跳转**：点击后仍进入提交订单页（见第 5.2 节），默认选中当前最优可用券，用户可更换其他券或取消使用优惠券后再下单。禁止在团购详情页直接调支付或直接下单（否则用户无法不用券）。提交订单页实付为 0 元时再跳过微信支付、直接生成订单。

### 7.10 团购详情领券提示模块【本次新增 · V3.0】

依据 2026-09-18 YAN 截图需求：用户未领取优惠券直接进入超值团购页，点开无券后价的商品后，在团购详情页底部（「立即购买」按钮上方）增加提示模块，引导先领券再下单。

**提示模块样式（设计稿）**：浅色提示条，左侧文案「可先领取优惠券，券后价格更优惠！」，右侧主色按钮「立即领券」。

**展示条件**（须同时满足）：

1. 当前团购商品存在至少一张 PC 端已配置、当前对该用户「可领取」的适用优惠券（可领取性按第 6.3.2 节领取侧配置判断：领取时间、总发放数量、每人领取次数、领取用户类型、领取会员限制等）；
2. 用户当前未持有该团购适用优惠券中任何一张「已领取且未使用」的券。判断仅看「已领未用」：**下单时该券是否满足使用条件（第 5.2 节置灰限制）不影响本判断**，只要存在已领未用的适用券，团购详情页就不展示提示模块（2026-09-18 YAN 澄清）。

**不展示与重新展示规则**（2026-09-18 YAN 补充确认）：

1. 用户持有至少一张该团购适用的「已领取且未使用」优惠券时，不展示提示模块（不论该券在下单选券时能否使用）；
2. 已领适用券**全部已使用/已失效**（不再持有已领未用的适用券），且仍存在可领取优惠券（如每人领取次数未达上限）时，提示模块**重新展示**，可再次进入领券流程；
3. 该团购无任何「可领取」优惠券时，直接不展示提示模块，**无 Toast 提示**；不可领取原因以 PC 端优惠券可领取限制配置为准（如已领完、达每人领取次数上限、不在领取时间内、领取用户类型不符等）；
4. **例外**：仅因「未认证会员」（领取会员限制=认证会员且当前用户非认证会员）导致不可领取时，仍展示提示模块；点击「立即领券」不跳转优惠券详情，改为弹出认证引导弹窗（样式与按钮同第 7.9 节：「取消」「立即认证」），「立即认证」进入认证会员信息输入流程。

**「立即领券」跳转规则**：

1. 该团购仅一张可领取优惠券时，跳转该优惠券的「优惠券详情」页（含使用规则、订单信息，底部「免费领取」，同第 7.2 节券详情口径）；
2. 该团购绑定多张优惠券时，默认跳转**优惠力度最大**的可领取优惠券详情；「优惠力度最大」=按当前团购商品计算券后实付金额最低的一张（口径同第 5.2 节默认选券）；
3. 多张优惠券中部分不可领取（不满足 PC 领取限制）时，跳转**可领取且优惠力度最大**的优惠券详情；
4. 多张可领券券后实付金额相同时，跳转**有效期临近**的优惠券详情（使用有效期截止日最近的一张；2026-09-18 YAN 确认）。

**领券后回流**：

1. 优惠券详情页点击「免费领取」→ 领取校验通过 → 进入领取成功页（第 7.4 节）；
2. 领取成功页底部按钮为「立即使用」（线下核验产品券口径，见第 7.4 节）→ 点击跳回该团购详情页；
3. 跳回后详情页价格按第 5.3 节「已领取该商品优惠券」展示「券后价」，提示模块因存在已领未用适用券而不再展示；
4. 点击「免费领取」时若领取校验失败（该券已领完 / 已达领取次数上限），按第 7.2 节既有 Toast 文案提示，不写入领取记录。

## 9. 异常与边界

| 场景 | 处理方式 |
| --- | --- |
| 优惠券总发放数量已达上限 | 提示「该优惠券已领完」；会员福利列表对应「免费领取」置灰。 |
| 当前用户已达领取次数上限 | 提示「您已达到该优惠券的领取上限」；「免费领取」置灰；已领未用可展示「去使用」。 |
| 优惠券领取时间未开始 | 不在小程序任何列表/券区展示，卡片不置灰、无 Toast；到达领取开始时间后自动恢复展示并沿用原排序号。已领取用户不受影响。 |
| 当前业务无可用优惠券 | 展示「无可用优惠券」或「暂无可用优惠券」（车况优惠券区域文案为「无可用优惠券」）。 |
| 优惠券抵扣金额高于订单金额 | 实付价按 0 元计算，详情展示「免费」；详情底钮文案可为「立即下单」，点击仍进提交订单页选券；提交订单页实付 0 元时直接下单。 |
| 优惠券已下架 | 已领未用仍可使用；选券弹窗不提示「该优惠券已下架」（与现网一致）。 |
| 微信支付成功后三次查询仍未确认 | 提示「支付结果确认中，可到优惠券/团购查看」；停留当前页，不跳购买成功页。 |
| 编辑团购时关闭团购价开关 | 小程序列表/详情/提交订单按原价展示与收款；不因残留团购价数字仍展示团购价。已购订单实付不变。 |
| 不可用原因为非认证用户 | 弹窗「非认证会员无法购买」，引导「立即认证」。 |
| 选券弹窗中其他不可用原因 | 按第 5.2 节 Toast 优先级提示；限制项来自 PC 优惠券配置。 |
| 团购详情无可领取优惠券（非认证原因除外） | 不展示领券提示模块（见第 7.10 节）。 |
| 仅因「未认证会员」不可领券 | 团购详情仍展示领券提示模块；点击「立即领券」弹认证引导弹窗（第 7.9 节同款），「立即认证」进入认证流程（见第 7.10 节）。 |
| 领券后跳回团购详情 | 价格更新为券后价，提示模块不再展示（见第 7.10 节）。 |
| 已领适用券全部用完/失效且仍有可领券 | 不再持有已领未用适用券，团购详情重新展示领券提示模块（见第 7.10 节）。 |
| 持有已领未用适用券但该券下单时不可用 | 团购详情仍不展示领券提示模块（提示只看已领未用，不看下单可用性，见第 7.10 节）。 |
