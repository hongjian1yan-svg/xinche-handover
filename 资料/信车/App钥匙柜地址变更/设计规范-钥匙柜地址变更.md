# 设计规范提取（来源：Figma "20260717锦和钥匙柜变更地址"）

来源节点：钥匙柜管理列表卡片（1:90 / 1:148 / 1:209）、详情页（4:88）、存入钥匙表单（1:268 / 1:339）、选择钥匙柜弹层（1:410）。
比例尺：Figma 画布为 750 宽（=375pt @2x），本预览统一按 **CSS px = Figma px / 2** 换算，保证间距/字号与设计稿严格对应。状态栏文字/图标同样要按此比例换算（"9:41" 是 30px SF Pro Semibold → 15px），不能凭感觉估一个更小的数字。

对应的可交互原型见 [交互原型/index.html](交互原型/index.html)；图标素材见 [交互原型/assets/icons/](交互原型/assets/icons/)。

## 数值口径澄清（重要，避免再算错一倍——已反复出错，务必牢记）
**用户说的所有 px 数字都是设计稿尺寸（2倍图），不是代码尺寸，永远要 /2，没有例外。**
不管这个数字是我自己从 Figma `get_design_context` 抓取的坐标，还是用户在对话里直接报的（哪怕是照着截图标注量出来的"36px""28px""12px"这种），一律按 750×1624 的 2 倍图换算成 375 宽的 1 倍代码尺寸，即 /2。
唯一例外：描边/线宽（border-width）——1px 描边就是字面 1px，不做 /2（否则会变成 0.5px 这种没有意义的值）。
图标素材导出尺寸同理也是 2 倍图（如 fanhui.svg 的 32×32），代码里渲染同样要 /2（→16px）。
（曾经错误地认为"用户在聊天里直接报的数字就是最终代码px、不用再换算"，导致多处间距翻倍，被用户明确纠正："我说的设计尺寸，不是代码尺寸，请你牢记"——这条是最终结论，以后不要再犹豫。）

## 关键结论 / 与旧版预览的差异
1. 门店/时间行、车架号等信息行文字颜色应为 `#333`，不是灰色 muted——旧版误用了灰色。
2. 卡片圆角、按钮尺寸、字号需按 /2 换算精确还原，旧版偏大偏松散。
3. 单选/勾选状态必须使用真实图标资源，不能用纯 CSS 圆点近似。
4. 加急标签、车位号/柜门号方框的双段结构（彩色表头+白底数值）需还原，不能简化成纯色徽标。
5. 「变更钥匙柜」「更多」为本迭代新增，设计稿未定义精确尺寸，沿用同一按钮组的字号(12px)/圆角(5px)/高度(27~28px)规格，横向等距排布，属于合理外推（已在 PRD 6.2 中说明）。
